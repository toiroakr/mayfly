The publish directory (docs/)

By convention mayfly publishes the GitHub Pages site from docs/, and mayfly keep places kept pages under docs/<path>. The folder name is the site root — it does not appear in the URL (docs/index.html → /, docs/commands/push/index.html → /commands/push/).

GitHub Pages (Actions deploy) can publish any folder, so the name is free — but it is hardcoded in a few places. To use a different folder (e.g. site/), change all of them so they stay in sync:

FileWhat to change
mayflyDOCS_DIR="docs" (used by keep to place files)
.github/workflows/pages.ymlthe upload-pages-artifact input path: docs, the trigger on.push.paths: ['docs/**'], and cd docs in the page-index step

If these drift apart, keep writes to one folder while Pages publishes another. (Legacy branch-based Pages only allows / or /docs; the Actions deploy mayfly uses has no such limit.)

Page order & structure

The sidebar mirrors the docs/ directory. Ordering is driven entirely by numeric directory prefixes — e.g. 10_getting-started/, 30_commands/10_push/. The prefix is stripped for display, so URLs/labels read cleanly.

  • Use consistent zero-padded widths (e.g. all two digits) so they sort correctly.
  • Leave gaps (10, 20, 30…) so you can insert pages later without renumbering.
  • The list comes from pages.json, generated at deploy by pages.yml; each page's label is its <title>.

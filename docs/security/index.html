Security & supply chain

Workflows

  • Actions pinned by commit SHA (not moving tags), with a version comment.
  • persist-credentials: false on every checkout.
  • Least privilege: jobs request only the permissions they use; the token is read-only unless a job must comment.
  • Fork PRs are skipped for commenting (their token is read-only).
  • Run-step inputs come via env:, never interpolated into shell.
  • zizmor statically lints the workflows in CI.

No bundled code

mayfly is bash + YAML with no third-party runtime dependencies. The CLI talks to the GitHub API via gh; the workflows use only GitHub's own actions. There is nothing to audit beyond what you can read.

Access control

Previews are artifacts and Pages in your own repo, so access follows the repo. Private repo ⇒ authenticated collaborators only. On GitHub Enterprise Cloud, set Pages visibility to private so kept pages are access-controlled too — unauthenticated requests are redirected to GitHub's auth flow.

Throwaway by default

Generated HTML lands on short-lived preview/* branches that auto-expire in 90 days; it never enters a branch you merge unless you explicitly keep it through a reviewed PR.
